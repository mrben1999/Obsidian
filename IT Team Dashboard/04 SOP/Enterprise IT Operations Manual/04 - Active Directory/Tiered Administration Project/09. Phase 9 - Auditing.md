# Phase 9 — Auditing

Liên quan: [[08. Phase 8 - GPO Security Baseline]] · [[../../09 - Monitoring/00. Module Overview]] · [[10. Phase 10 - Privileged Access Management]]

## 1. Mục đích
Không thể bảo vệ những gì không nhìn thấy — Auditing đảm bảo mọi hành vi quan trọng trong AD (đăng nhập, đổi quyền, đổi cấu trúc AD, truy cập tài nguyên nhạy cảm) đều được ghi log và có thể truy vết khi có sự cố.

## 2. Phạm vi áp dụng
Domain Controller, Server Tier 1 quan trọng (File Server, SQL, GLPI), tài khoản Admin các Tier.

## 3. Điều kiện tiên quyết
- [ ] Đã hoàn tất Phase 5 (Tier) và Phase 8 (GPO Baseline).
- [ ] Đã xác định điểm tập trung log (SIEM/Syslog server, hoặc tối thiểu 1 máy chủ Windows Event Collector).

## 4. Quy trình thực hiện

### Bước 1 — Bật Advanced Audit Policy trên Domain Controller
`GPO "Default Domain Controllers Policy"` → `Computer Configuration > Policies > Windows Settings > Security Settings > Advanced Audit Policy Configuration`:

| Danh mục | Audit Success | Audit Failure |
|---|---|---|
| Account Logon | ✅ | ✅ |
| Account Management | ✅ | ✅ |
| Directory Service Access | ✅ | ✅ |
| Logon/Logoff | ✅ | ✅ |
| Object Access | ✅ (chỉ với object đã bật SACL cụ thể) | ✅ |
| Policy Change | ✅ | ✅ |
| Privilege Use | ✅ | ✅ |

```powershell
# Bật qua auditpol (thực hiện trên từng DC hoặc qua GPO)
auditpol /set /subcategory:"Logon" /success:enable /failure:enable
auditpol /set /subcategory:"User Account Management" /success:enable /failure:enable
auditpol /set /subcategory:"Directory Service Changes" /success:enable /failure:enable
auditpol /set /subcategory:"Sensitive Privilege Use" /success:enable /failure:enable
```

### Bước 2 — Bật audit object access cho OU nhạy cảm (Admin Accounts, Tier0-DC)
```powershell
# Qua ADUC: chuột phải OU=Admin Accounts > Properties > Security > Advanced > Auditing > Add
# Audit: Everyone, áp dụng cho "Write All Properties", "Delete", "Modify Permissions" -> Success + Failure
```

### Bước 3 — Windows Event Forwarding (WEF) tập trung log về 1 máy chủ
```powershell
# Trên Collector Server
wecutil qc /q

# Trên từng Source (DC, Server quan trọng) - cấu hình qua GPO
# Computer Configuration > Administrative Templates > Windows Components > Event Forwarding
# Configure target Subscription Manager: Server=http://logcollector.company.local:5985/wsman/SubscriptionManager/WEC,Refresh=60
```

### Bước 4 — Forward log ra SIEM/Syslog (nếu có, ví dụ tích hợp với hệ giám sát hiện có)
```
DC → Windows Event Forwarding → Log Collector Server → Syslog/SIEM Agent → SIEM (Zabbix/Grafana/Splunk...)
```
Chi tiết cấu hình giám sát cụ thể xem [[../../09 - Monitoring/00. Module Overview]].

### Bước 5 — Đồng bộ sự kiện quan trọng vào GLPI (Ticket tự động khi có cảnh báo nghiêm trọng)
Với sự kiện mức Critical (ví dụ thêm thành viên vào Domain Admins ngoài giờ hành chính), cấu hình script/webhook tạo Ticket GLPI tự động — tham khảo cơ chế Webhook/API tại tài liệu GLPI Deployment Manual (`08. Automation/Actions`).

## 5. Kiểm tra sau triển khai
```powershell
auditpol /get /category:*   # xác nhận toàn bộ category quan trọng đã bật Success+Failure
```
- [ ] Event ID 4720 (tạo user), 4728/4732 (thêm thành viên group nhạy cảm), 4740 (account lockout) xuất hiện đúng khi test thử.
- [ ] Log được forward thành công về Collector Server (kiểm tra `wevtutil qe ForwardedEvents`).

## 6. Rollback (nếu có)
Nếu bật quá nhiều audit category gây log tăng đột biến, ảnh hưởng hiệu năng/disk DC:
```powershell
auditpol /set /subcategory:"Object Access" /success:disable
```
Tắt bớt category ít giá trị, giữ lại các category cốt lõi (Logon, Account Management, Privilege Use).

## 7. Kiểm tra bảo mật
- [ ] Đặc biệt giám sát chặt Event ID **4728/4732/4756** (thêm thành viên vào Domain Admins/Enterprise Admins/Schema Admins) — đây là dấu hiệu leo thang đặc quyền nghiêm trọng nhất cần cảnh báo tức thời.
- [ ] Log Collector Server phải nằm trong Tier 0 hoặc được bảo vệ tương đương — nếu kẻ tấn công xóa được log, toàn bộ nỗ lực Auditing vô nghĩa.

## 8. Troubleshooting
| Sự cố | Nguyên nhân | Cách xử lý |
|---|---|---|
| Log không được forward về Collector | Chưa cấu hình đúng Subscription hoặc firewall chặn WinRM (port 5985) | Kiểm tra `winrm quickconfig` trên Source, mở port 5985 |
| Log DC tăng dung lượng quá nhanh | Bật audit Object Access cho quá nhiều object không cần thiết | Thu hẹp phạm vi SACL chỉ cho OU/object thực sự nhạy cảm |
