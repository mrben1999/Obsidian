# Phase 4 — Chuẩn hóa Service Account

Liên quan: [[03. Phase 3 - Security Groups (AGDLP)]] · [[05. Phase 5 - Tiered Administration]] · [[../../13 - ITSM (GLPI)/00. Module Overview]]

## 1. Mục đích
Loại bỏ hoàn toàn việc chạy Windows Service (SQL, GLPI/IIS, Backup, Print Spooler...) bằng tài khoản Administrator/Domain Admin — một trong những lỗ hổng credential phổ biến nhất (mật khẩu service account thường không đổi trong nhiều năm, dễ bị khai thác qua Kerberoasting).

## 2. Phạm vi áp dụng
Toàn bộ dịch vụ Windows chạy dưới tài khoản domain: SQL Server, IIS/GLPI, Backup Agent, Scan-to-folder, Print Server.

## 3. Điều kiện tiên quyết
- [ ] Đã hoàn tất Phase 2 (OU `Service Accounts` đã tồn tại).
- [ ] Domain Functional Level ≥ Windows Server 2012 để dùng **group Managed Service Account (gMSA)** — xác nhận tại [[00. Roadmap]].
- [ ] Đã kiểm kê danh sách toàn bộ service hiện đang chạy bằng tài khoản Admin.

## 4. Quy trình thực hiện

### Bước 1 — Tạo KDS Root Key (bắt buộc 1 lần cho toàn forest, cần thiết cho gMSA)
```powershell
Add-KdsRootKey -EffectiveTime ((Get-Date).AddHours(-10))
# Lưu ý: bình thường cần đợi 10 giờ để nhân rộng key trên toàn forest,
# dùng -EffectiveTime lùi lại 10 giờ chỉ áp dụng cho môi trường test/lab, không dùng cho production thật
```

### Bước 2 — Tạo Service Account truyền thống (cho hệ thống chưa hỗ trợ gMSA, ví dụ 1 số ứng dụng cũ)
```powershell
$Password = ConvertTo-SecureString "Random-Strong-Password-Here!29xZ" -AsPlainText -Force
New-ADUser -Name "svc_glpi" -SamAccountName "svc_glpi" `
  -UserPrincipalName "svc_glpi@company.local" `
  -Path "OU=Service Accounts,DC=company,DC=local" `
  -AccountPassword $Password -Enabled $true `
  -PasswordNeverExpires $true -CannotChangePassword $true

# Chặn đăng nhập tương tác (Cannot login locally / Deny logon locally qua GPO)
```

### Bước 3 — Tạo gMSA (khuyến nghị cho hệ thống hỗ trợ, mật khẩu tự đổi 30 ngày, không ai biết mật khẩu)
```powershell
New-ADServiceAccount -Name "svc_sql_gmsa" `
  -DNSHostName "HQ-PRD-SQL-01.company.local" `
  -PrincipalsAllowedToRetrieveManagedPassword "HQ-PRD-SQL-01$" `
  -Path "OU=Service Accounts,DC=company,DC=local"

# Cài đặt gMSA trên server sử dụng
Install-ADServiceAccount -Identity "svc_sql_gmsa"
Test-ADServiceAccount -Identity "svc_sql_gmsa"   # phải trả True
```

### Bước 4 — Áp dụng Deny logon locally qua GPO cho toàn bộ Service Account
`OU=Service Accounts` → GPO riêng → `Computer Configuration > Policies > Windows Settings > Security Settings > Local Policies > User Rights Assignment > Deny log on locally` → thêm nhóm chứa toàn bộ service account.

### Bước 5 — Danh sách service account chuẩn cho hạ tầng hiện tại
| Tài khoản | Dùng cho | Loại |
|---|---|---|
| `svc_glpi` | IIS Application Pool chạy GLPI | Traditional (nếu IIS chưa hỗ trợ gMSA) |
| `svc_backup` | Backup Agent (Veeam/Windows Server Backup) | Traditional |
| `svc_sql_gmsa` | SQL Server Service | gMSA |
| `svc_scan` | Scan-to-folder trên máy in đa năng | Traditional |
| `svc_printer` | Print Spooler service (nếu cần chạy dưới tài khoản domain) | Traditional |

## 5. Kiểm tra sau triển khai
```powershell
Get-ADServiceAccount -Filter * | Select Name, Enabled
Get-ADUser -Filter 'SamAccountName -like "svc_*"' -SearchBase "OU=Service Accounts,DC=company,DC=local" -Properties PasswordNeverExpires, CannotChangePassword
```
- [ ] Không còn service nào chạy bằng tài khoản Domain Admin/Administrator.
- [ ] Toàn bộ service account có `Deny logon locally`.
- [ ] gMSA đã test thành công (`Test-ADServiceAccount` trả `True`).

## 6. Rollback (nếu có)
Nếu service không khởi động được sau khi đổi sang service account mới, tạm thời chuyển lại tài khoản chạy service cũ **trong khung giờ bảo trì**, kiểm tra lại quyền NTFS/SQL Login của service account mới trước khi thử lại.

## 7. Kiểm tra bảo mật
- [ ] Service account **không** là thành viên của bất kỳ nhóm Admin nào (Domain Admin, Server Admin) — chỉ cấp đúng quyền tối thiểu cần thiết trên tài nguyên cụ thể (ví dụ SQL Login riêng, NTFS quyền riêng thư mục GLPI).
- [ ] Rà soát Service Principal Name (SPN) không bị trùng/thừa (nguy cơ Kerberoasting):
```powershell
setspn -L svc_glpi
```

## 8. Troubleshooting
| Sự cố | Nguyên nhân | Cách xử lý |
|---|---|---|
| `Test-ADServiceAccount` trả `False` | Chưa cài `Install-ADServiceAccount` trên đúng server, hoặc KDS Root Key chưa nhân rộng đủ | Đợi đủ thời gian nhân rộng (production thật), kiểm tra lại `PrincipalsAllowedToRetrieveManagedPassword` |
| Service không start, báo lỗi logon failure | Sai mật khẩu service account trong Service Manager, hoặc thiếu quyền "Log on as a service" | Cấp quyền qua GPO `User Rights Assignment > Log on as a service` |
