# Phase 4 — Giám sát SNMP Switch/Router

Liên quan: [[03. Phase 3 - Agent Windows]] · [[../../06 - Network/00. Module Overview]]

## 1. Mục đích
Giám sát thiết bị không cài được Agent (Switch/Router/Firewall/AP) qua SNMP — khác biệt với GLPI Inventory (GLPI dùng SNMP để *kiểm kê tài sản*, Zabbix dùng SNMP để *giám sát tình trạng real-time*: CPU switch, trạng thái port, băng thông).

## 2. Phạm vi áp dụng
Core Switch, Access Switch, Router, Firewall (nếu hỗ trợ SNMP).

## 3. Điều kiện tiên quyết
- [ ] Phase 1 hoàn tất.
- [ ] Thiết bị mạng đã bật SNMP (thường dùng chung community string đã cấu hình cho GLPI Inventory nếu có, hoặc tạo riêng cho Zabbix).

## 4. Quy trình thực hiện

### Bước 1 — Bật SNMP trên thiết bị (ví dụ Switch Cisco)
```
snmp-server community ZBX_readonly RO
snmp-server location "HQ - Tang 1 - Core Switch"
snmp-server contact "it@company.local"
```

### Bước 2 — Tạo Host trên Zabbix cho từng thiết bị mạng
`Data collection > Hosts > Create host`:
| Trường | Giá trị |
|---|---|
| Host name | `HQ-SW-CORE-01` (theo [[../../01 - Governance/04. Naming Convention]]) |
| Interfaces | Loại **SNMP**, port 161, SNMP version 2 (hoặc SNMPv3 nếu switch hỗ trợ — khuyến nghị hơn vì mã hóa) |
| SNMP community | `ZBX_readonly` |
| Templates | `Cisco IOS SNMP` (hoặc template đúng hãng — Zabbix có sẵn template cho Cisco, HP/Aruba, MikroTik, Ubiquiti...) |

### Bước 3 — Ưu tiên SNMPv3 cho thiết bị hỗ trợ (bảo mật hơn v2c)
```
snmp-server group ZBXGroup v3 auth
snmp-server user zbxuser ZBXGroup v3 auth sha AuthPass2026! priv aes 128 PrivPass2026!
```
Trên Zabbix Host Interface, chọn SNMP version 3, nhập đúng thông tin auth/priv tương ứng.

### Bước 4 — Bulk import nhiều thiết bị cùng lúc (nếu số lượng switch/AP lớn)
`Data collection > Hosts > Import` — dùng file CSV/XML export sẵn từ danh sách switch trong [[../../06 - Network/00. Module Overview]], tránh tạo tay từng host khi số lượng nhiều.

### Bước 5 — Network Discovery tự động phát hiện thiết bị mới (tùy chọn nâng cao)
`Data collection > Discovery > Create discovery rule` — quét dải IP, tự động thêm host mới phát hiện qua SNMP vào nhóm mặc định, giảm công sức thêm tay từng thiết bị mới lắp đặt.

## 5. Kiểm tra sau triển khai
- [ ] Host switch/router chuyển xanh, `Latest data` hiển thị CPU/Memory/Interface traffic.
- [ ] Trigger mặc định của template (ví dụ "High CPU utilization") hoạt động khi test giả lập tải cao.

## 6. Rollback (nếu có)
Gỡ Host khỏi Zabbix nếu gây nhiễu, không ảnh hưởng thiết bị vật lý (SNMP chỉ đọc — read-only).

## 7. Kiểm tra bảo mật
- [ ] Ưu tiên tuyệt đối SNMPv3 cho thiết bị hỗ trợ — SNMPv2c gửi community string dạng cleartext.
- [ ] Với Router biên (edge, nối trực tiếp Internet) — áp dụng đúng nguyên tắc đã có trong GLPI Deployment Manual: **không bật SNMP** trên thiết bị này dù chỉ read-only, nhập giám sát thủ công hoặc qua kênh riêng biệt an toàn hơn.

## 8. Troubleshooting
| Sự cố | Nguyên nhân | Cách xử lý |
|---|---|---|
| Host đỏ, không lấy được dữ liệu SNMP | Sai community string, hoặc firewall chặn UDP 161 | Test bằng `snmpwalk -v2c -c ZBX_readonly <IP>` từ Zabbix Server trước |
| Template không khớp, thiếu metric quan trọng | Chọn nhầm template không đúng hãng thiết bị | Tìm đúng template Zabbix Official theo hãng, hoặc tùy chỉnh thêm Item riêng |
