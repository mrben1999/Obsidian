# Bulk Import Script — Nhập hàng loạt bài KB qua REST API

Liên quan: [[01. KB Setup Guide]] · [[02. Category Structure]]

## Checklist
- [ ] Bật API trong `Setup > General > API`
- [ ] Tạo App-Token riêng cho script import (không dùng chung token khác)
- [ ] Tạo trước cây Category theo [[02. Category Structure]] (script không tự tạo Category)
- [ ] Cài `pandoc` để convert Markdown → HTML
- [ ] Chạy thử trên 1-2 bài trước khi chạy hàng loạt toàn bộ ~30 bài

## Command

### Bước 1 — Chuẩn bị môi trường
```bash
apt install -y pandoc jq curl
```

### Bước 2 — Lấy Session Token
```bash
GLPI_URL="http://glpi.qve.com/apirest.php"
USER_TOKEN="YOUR_USER_TOKEN"
APP_TOKEN="YOUR_APP_TOKEN"

SESSION_TOKEN=$(curl -s -X GET "$GLPI_URL/initSession" \
  -H "Authorization: user_token $USER_TOKEN" \
  -H "App-Token: $APP_TOKEN" | jq -r '.session_token')

echo "Session: $SESSION_TOKEN"
```

### Bước 3 — Lấy ID Category tương ứng (đã tạo sẵn trong GLPI)
```bash
curl -s -X GET "$GLPI_URL/KnowbaseItemCategory" \
  -H "Session-Token: $SESSION_TOKEN" -H "App-Token: $APP_TOKEN" | jq '.[] | {id, name}'
```
Ghi lại ID từng Category, dùng cho bước map bên dưới.

### Bước 4 — Script import hàng loạt từ thư mục Markdown
```bash
cat > import-kb.sh << 'SCRIPT'
#!/bin/bash
GLPI_URL="http://glpi.qve.com/apirest.php"
SESSION_TOKEN="$1"
APP_TOKEN="$2"
CATEGORY_ID="$3"
VISIBILITY="$4"   # "public" hoặc "technician"
MD_FILE="$5"

TITLE=$(grep -m1 "^# " "$MD_FILE" | sed 's/^# //')
BODY_HTML=$(pandoc "$MD_FILE" -f markdown -t html --wrap=none)

# Escape để nhét vào JSON an toàn
BODY_JSON=$(echo "$BODY_HTML" | jq -Rs .)

PAYLOAD=$(cat << JSON
{
  "input": {
    "name": "$TITLE",
    "answer": $BODY_JSON,
    "knowbaseitemcategories_id": $CATEGORY_ID,
    "is_faq": 1
  }
}
JSON
)

RESULT=$(curl -s -X POST "$GLPI_URL/KnowbaseItem" \
  -H "Session-Token: $SESSION_TOKEN" -H "App-Token: $APP_TOKEN" \
  -H "Content-Type: application/json" -d "$PAYLOAD")

echo "Đã tạo: $TITLE -> $RESULT"
SCRIPT
chmod +x import-kb.sh

# Ví dụ chạy cho 1 file, Category ID = 5 (thay theo ID thật lấy ở Bước 3)
./import-kb.sh "$SESSION_TOKEN" "$APP_TOKEN" 5 public "1.1 Accounts & Passwords/[AD] Đổi mật khẩu Windows-AD.md"
```

### Bước 5 — Cấu hình Visibility (Target) sau khi tạo bài
API tạo bài xong mặc định **private** — cần gọi thêm endpoint gán Visibility (`KnowbaseItem_Profile`, `KnowbaseItem_Entity`) hoặc thao tác tay 1 lần trên giao diện cho nhanh với số lượng ~30 bài (script REST API cho bước Visibility phức tạp hơn, khuyến nghị làm tay để tránh cấp nhầm quyền cho bài nội bộ nhạy cảm — xem bảng phân quyền tại [[01. KB Setup Guide]]).

## Verify
```bash
curl -s -X GET "$GLPI_URL/KnowbaseItem" -H "Session-Token: $SESSION_TOKEN" -H "App-Token: $APP_TOKEN" | jq '. | length'
```
Đối chiếu số lượng bài đã tạo với tổng số file Markdown đã import.

## Troubleshooting
| Lỗi | Nguyên nhân | Cách xử lý |
|---|---|---|
| API trả 401 Unauthorized | Token sai/hết hạn session | Gọi lại `initSession` lấy session token mới |
| HTML bị lỗi định dạng khi hiển thị trong GLPI | Pandoc convert bảng/mermaid không tương thích TinyMCE | Với bài có bảng phức tạp/mermaid diagram, nên nhập tay qua giao diện thay vì API |
| Bài tạo xong nhưng không ai thấy | Chưa cấu hình Visibility (mặc định private) | Thực hiện Bước 5, kiểm tra lại tab Visibility trên từng bài |

## Ghi chú thực tế
- Với ~30 bài hiện có, cách thực tế nhất: chạy script cho phần "answer" (nội dung), sau đó dành khoảng 30-45 phút thao tác tay trên giao diện để gán đúng Visibility cho từng bài theo đúng bảng phân quyền — nhanh hơn và an toàn hơn so với viết thêm script phức tạp cho phần phân quyền.
- Mermaid diagram trong các bài (nếu có) sẽ **không** tự render trong GLPI như trong Obsidian — GLPI không hỗ trợ mermaid native. Với các bài có sơ đồ (ví dụ sơ đồ mạng), nên chụp ảnh sơ đồ và đính kèm trực tiếp vào bài thay vì giữ nguyên code mermaid.
