# Setup Guide — Cấu hình Knowledge Base trong GLPI 11.0.8

## 1. Vị trí quản lý Knowledge Base
- **Xem/tra cứu bài viết:** `Tools > Knowledge base` — đây là nơi mọi người dùng (tùy quyền) vào đọc/tìm bài viết, tương ứng URL `http://glpi.qve.com/front/knowbaseitem.php`.
- **Tạo bài viết mới:** `Tools > Knowledge base > Add a new article` (nút "+" góc trên bên phải màn hình danh sách KB).
- **Quản lý Category (danh mục KB):** `Setup > Dropdowns > Knowledge base category` — đây là nơi tạo cây danh mục (không nằm trong Administration > Rules hay Assets, mà nằm trong nhóm Dropdown vì Category KB được xem là 1 loại dropdown dùng chung).

## 2. Tạo cây Category theo cấu trúc Quảng Việt
Vào `Setup > Dropdowns > Knowledge base category > Add`, tạo lần lượt theo đúng thứ tự cha-con dưới đây (chọn "Parent category" tương ứng khi tạo mục con):

```
1. End-User Self-Service
   1.1 Accounts & Passwords
   1.2 Network & Connectivity
   1.3 Office Equipment
   1.4 Application Software
2. IT Policies & Procedures
   2.1 Device Provisioning
   2.2 Infosec Policy
   2.3 Procurement
3. IT Operations (Technician Only)
   3.1 GLPI Playbook
   3.2 Infrastructure & Server
   3.3 Maintenance & Monitoring
4. Troubleshooting / Known Errors
   4.1 Hardware
   4.2 Software
```
Xem chi tiết cây đầy đủ + mã category đề xuất tại [[02. Category Structure]].

## 3. Phân quyền hiển thị (Visibility / Target) — quan trọng nhất
GLPI KB **không phân quyền theo Category** mà phân quyền **theo từng bài viết (article)**, qua tab **"Visibility"** khi tạo/sửa bài viết. Đây là điểm khác biệt quan trọng cần lưu ý khi nhập liệu:

| Danh mục | Đối tượng xem | Cách cấu hình tab Visibility |
|---|---|---|
| 1. End-User Self-Service | Toàn bộ nhân viên (Self-Service Profile) | Target = **Entity gốc "Quảng Việt"**, Profile = **tất cả Profile** (bao gồm Self-Service), tick "Recursive" để áp cho cả entity con (HN/HCM) |
| 2. IT Policies & Procedures | Toàn bộ nhân viên | Giống mục 1 |
| 3. IT Operations (Technician Only) | **Chỉ nhóm IT** | Target = Profile **Technician** + **Super-Admin** + **Supervisor** — **KHÔNG** thêm Profile Self-Service |
| 4. Troubleshooting / Known Errors | **Chỉ nhóm IT** (là tài liệu tra cứu nội bộ khi xử lý ticket) | Giống mục 3 |

> ⚠️ Nếu quên cấu hình tab Visibility, mặc định bài viết mới thường **private** (chỉ người tạo thấy) — luôn kiểm tra lại bước này trước khi coi bài viết đã "publish" xong.

## 4. Bật gợi ý KB trên Self-Service Portal (giảm tải ticket)
`Setup > General > Assistance` (trước đây là "Trợ giúp") → bật tùy chọn gợi ý bài KB liên quan ngay khi người dùng gõ tiêu đề Ticket trên Self-Service Portal — hệ thống tự động search full-text trong KB và gợi ý bài viết trùng khớp trước khi cho phép submit ticket.

## 5. Checklist triển khai KB
- [ ] Tạo đủ cây Category theo [[02. Category Structure]]
- [ ] Nhập toàn bộ bài viết theo mẫu tại [[03. Article Template]]
- [ ] Cấu hình đúng Visibility cho từng bài (đặc biệt mục 3, 4 — không để lộ tài liệu kỹ thuật nội bộ ra Self-Service)
- [ ] Bật gợi ý KB trên Self-Service Portal
- [ ] Thông báo toàn công ty về việc có Self-Service Portal + KB (giảm tải ticket cấp 1)
- [ ] Định kỳ review/cập nhật bài viết (tối thiểu hàng quý — xem mục "Lịch sử cập nhật" trong từng bài)

## 6. Cách đưa nội dung Markdown trong bộ tài liệu này vào GLPI
GLPI dùng trình soạn thảo Rich Text (TinyMCE), lưu nội dung dạng HTML. Có 2 cách:
1. **Thủ công (khuyến nghị cho từng bài lẻ):** Copy nội dung từng phần (Symptom/Root Cause/Resolution/Notes) trong file `.md`, dán vào ô "Description" của bài viết GLPI, dùng toolbar để bôi đậm/heading lại (mất khoảng 3-5 phút/bài).
2. **Hàng loạt (khuyến nghị khi nhập 20+ bài cùng lúc):** Dùng script REST API tại [[04. Bulk Import Script]] — script tự convert Markdown sang HTML (qua `pandoc`) và gọi API tạo bài viết + gán đúng Category/Visibility tự động.
