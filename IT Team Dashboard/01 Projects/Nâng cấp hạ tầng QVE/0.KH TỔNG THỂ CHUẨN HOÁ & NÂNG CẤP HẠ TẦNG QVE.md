## LỜI MỞ ĐẦU TỪ KIẾN TRÚC SƯ TRƯỞNG

Nhận xét và chỉ đạo từ Ban Giám đốc (BGĐ) cùng những phân tích thực tế của anh là vô cùng chính xác, sắc bén và thể hiện đúng bản chất của quản trị hạ tầng doanh nghiệp.

Thách thức lớn nhất trong dự án này không phải là công nghệ mới của Windows Server 2022, mà là **Sự tồn tại của các hệ thống Legacy (Windows XP, Windows 7, Windows Server 2012 R2, phần mềm chuyên dụng, máy công nghiệp/CNC)**. Nếu áp dụng tư duy "Security lý thuyết" ép toàn bộ hệ thống theo Microsoft Security Baseline hay CIS Benchmark hiện đại, xác suất làm sập dây chuyền sản xuất và ngưng trệ ứng dụng nghiệp vụ là **gần như 100%**.

Một hệ thống bảo mật xuất sắc không phải là hệ thống chặn đứng mọi kết nối, mà là hệ thống **đảm bảo hoạt động kinh doanh (Business Continuity) vận hành liên tục, ổn định trên một nền tảng rủi ro được kiểm soát (Controlled Risk)**.

Toàn bộ bản Master Blueprint dưới đây đã được tái cấu trúc hoàn toàn, tích hợp 10 nhận xét chiến lược của BGĐ, xây dựng **Compatibility Matrix**, bổ sung **Giai đoạn 2.5 (Compatibility & Risk Validation)**, phân tầng **Tiered Hardening Strategy**, thiết lập **Go/No-Go Decision Gate** và **Rollback Plan chi tiết cho từng hạng mục Change**.

# GIAI ĐOẠN 1: EMERGENCY BACKUP & QUICK WINS (Tuần 1 - Tuần 2)

### WHY

Trước khi tiến hành khảo sát hay thay đổi, hệ thống phải có "lưới an toàn". Đồng thời, triển khai ngay các **Quick Wins** — những công việc rủi ro bằng 0 nhưng mang lại hiệu quả bảo mật tức thì để giảm diện tấn công mà không ảnh hưởng tới vận hành.

### HOW

#### 1.1 Khôi phục & Thử nghiệm Backup (Immutable & Isolated Recovery Boundary)

- **Xác nhận bản Backup:** Kiểm tra các bản sao lưu System State và Bare-Metal Recovery (BMR) của toàn bộ Domain Controller (DC).
    
- **Diễn tập Restore trong Isolated Lab (BẮT BUỘC):**
    
    1. Dựng Isolated VLAN (không route ra ngoài Internet, không kết nối Production).
        
    2. Restore 01 DC nắm giữ FSMO Roles từ bản backup.
        
    3. Chạy `dcdiag /test:dns` và `repadmin /showrepl` trong môi trường Lab để đảm bảo bản backup **Khôi phục thành công 100%**.
        

#### 1.2 Triển khai danh mục "Quick Wins" (Rủi ro = 0, Cấu hình độc lập)

- **Q-01:** Khóa/Vô hiệu hóa (Disable) toàn bộ tài khoản Inactive > 90 ngày.
    
- **Q-02:** Đổi mật khẩu tài khoản **Built-in Administrator** (độ dài $\ge 25$ ký tự) và mật khẩu **DSRM** trên từng DC (`ntdsutil "set dsrm password" "reset on server null" q q`).
    
- **Q-03:** Bật Audit Logging nâng cao trên GPO (Audit Logon/Logoff, Account Management).
    
- **Q-04:** Kiểm tra và đồng bộ thời gian (NTP) toàn mạng về Core Switch/PDC Emulator.
    
- **Q-05:** Backup toàn bộ GPO hiện tại ra file lưu trữ (`Backup-GPO -All -Path C:\GPO_Backup`).
    
- **Q-06:** Khởi tạo và cập nhật dữ liệu tài sản máy tính/server vào hệ thống **GLPI**.
    

### ACCEPTANCE CRITERIA (Tiêu chí nghiệm thu Phase 1)

- [x] Restore thành công DC trong môi trường Isolated Lab, dịch vụ AD DS và DNS khởi chạy không lỗi.
    
- [x] 100% tài khoản Inactive > 90 ngày bị khóa.
    
- [x] Mật khẩu Administrator gốc và DSRM đã được thay đổi.
    
- [x] Bản Backup GPO hiện tại đã lưu trữ an toàn.
    

# GIAI ĐOẠN 2: KHẢO SÁT CHUYÊN SÂU TOÀN DIỆN HẠ TẦNG (Tuần 3 - Tuần 5)

Thu thập toàn bộ bức tranh hiện trạng của hệ thống Active Directory, DNS, DHCP, GPO, VMware, Network và đặc biệt là hệ thống Legacy.

### HOW: PHÂN LOẠI TÀI SẢN NGAY TỪ KHẢO SÁT (ASSET TIERING)

Toàn bộ máy tính/server trong Domain QVE phải được phân loại ngay thành **3 Tiers**:

- **Tier A (Modern Zone):** Windows 11, Windows 10 (Phiên bản 21H2+), Windows Server 2019/2022.
    
- **Tier B (Extended Legacy Zone):** Windows 7, Windows Server 2008 R2/2012 R2 (Đã patch TLS 1.2 & SHA-2).
    
- **Tier C (Restricted Legacy Zone):** Windows XP, Windows Server 2003, Các máy điều khiển CNC, Laser, Cân, PLC, Barcode, Camera.

# GIAI ĐOẠN 2.5: COMPATIBILITY & RISK VALIDATION (Tuần 6 - Tuần 7)

# GIAI ĐOẠN 3: TÁI CẤU TRÚC, PHÂN TẦNG VÀ HARDENING (Tháng 2 - Tháng 3)

### WHY

Gia cố hệ thống dựa trên nguyên tắc **Phân tầng (Tiered Hardening)**. Không bao giờ áp dụng một chính sách chung (Blanket Policy) cho toàn bộ Domain.

### HOW

#### 3.1 Tái cấu trúc Active Directory Organizational Unit (OU Structure)

Tạo cấu trúc OU mới tách biệt hoàn toàn giữa các Tier để quản lý GPO chuẩn xác:

```
DC=qve,DC=local
 ├── OU=QVE_Admin_Tiers (Tiering Model)
 │    ├── OU=Tier0_Identity (DCs, PKI)
 │    ├── OU=Tier1_Servers (App, DB, File Servers)
 │    └── OU=Tier2_Devices (Workstations, Admin PCs)
 ├── OU=QVE_Workstations
 │    ├── OU=TierA_Windows11_10 (Full Baseline)
 │    ├── OU=TierB_Windows7 (Selective Baseline)
 │    └── OU=TierC_Legacy_XP (Compensating Controls Only)
 └── OU=QVE_Servers
      ├── OU=Member_Servers
      └── OU=Legacy_Servers
```

#### 3.2 Lộ trình Triển khai Hardening Theo Nhóm (Tiered GPO Deployment)

Chiến lược đẩy GPO theo thứ tự an toàn: **OU Test/Pilot -> Tier A (Win 11/10) -> Member Servers -> Tier B (Win 7) -> Tier C (Legacy XP)**.

```
                  ┌─────────────────────────────────────────────────┐
                  │          GPO DEPLOYMENT SEQUENCE                │
                  └────────────────────────┬────────────────────────┘
                                           │
 ┌─────────────────┐      ┌────────────────▼┐      ┌─────────────────┐      ┌─────────────────┐
 │ 1. Pilot OU     │ ───> │ 2. Tier A       │ ───> │ 3. Member Server│ ───> │ 4. Tier B/C     │
 │    (IT Dept)    │      │    (Win 11/10)  │      │    (Win 2019/22) │      │    (Legacy OS)  │
 └─────────────────┘      └─────────────────┘      └─────────────────┘      └─────────────────┘
```

##### Chi tiết Cấu hình Hardening cho từng Tier:

##### A. Đối với Tier A (Windows 11 / Windows 10) - Áp dụng 100% Security Baseline:

- Bắt buộc SMB Signing, LDAP Signing, LDAP Channel Binding.
    
- Tắt hoàn toàn SMBv1, NTLMv1, RC4, TLS 1.0, TLS 1.1.
    
- Bật **Windows LAPS**, **Credential Guard**, **LSA Protection**.
    
- Áp dụng Microsoft Security Baseline v2022 via GPO.
    

##### B. Đối với Tier B (Windows 7 Updated) - Selective Hardening:

- Bắt buộc cập nhật bản vá KB3140245 (TLS 1.2) và SHA-2 Code Signing Support.
    
- Cho phép NTLMv2 (Tắt NTLMv1). Bật SMB Signing.
    
- Tắt SMBv1 (Nếu không kết nối với máy in/scan cũ).
    
- Bật Legacy LAPS (LAPS v1).
    

##### C. Đối với Tier C (Windows XP / Máy CNC) - Compensating Controls GPO:

- **KHÔNG ÁP DỤNG** Microsoft Security Baseline.
    
- Giữ nguyên NTLMv1/SMBv1 nếu ứng dụng yêu cầu.
    
- Bật GPO restriction: Cấm 100% tài khoản `Domain Admin` / `Tier 0 Admin` đăng nhập vào các máy này (`Deny log on locally`, `Deny log on through RDP`).
    
- Quản trị viên chỉ dùng tài khoản **Local Administrator riêng biệt** cho từng máy.
    

#### 3.3 Chuyển đổi SYSVOL sang DFSR (Chi tiết các bước thực thi)

Dành riêng cho trường hợp hệ thống hiện tại vẫn dùng FRS:

PowerShell

```
# Bước 1: Chuyển sang Prepared State (State 1)
dfsrmig /setglobalstate 1
# Kiểm tra đến khi tất cả DCs báo "Prepared"
dfsrmig /getmigrationstate

# Bước 2: Chuyển sang Redirected State (State 2)
dfsrmig /setglobalstate 2
dfsrmig /getmigrationstate

# Bước 3: Chuyển sang Eliminated State (State 3 - Hoàn tất)
dfsrmig /setglobalstate 3
dfsrmig /getmigrationstate
```

### ACCEPTANCE CRITERIA (Tiêu chí nghiệm thu Phase 3)

- [x] SYSVOL Migration hoàn tất đạt trạng thái **Eliminated State (DFSR)**.
    
- [x] Cấu trúc OU mới đã được triển khai và gán đúng GPO theo Tiering.
    
- [x] 100% máy tính Tier C đã được di chuyển vào VLAN Cô lập và kiểm tra **Block Internet Outbound** thành công trên Firewall.
    
- [x] Windows LAPS hoạt động tốt trên Tier A (Mật khẩu Local Admin tự xoay vòng lưu trên AD).
    

# GIAI ĐOẠN 4: AD MIGRATION, APPLICATION TESTING & DEMOTE (Tháng 4 - Tháng 6)

### WHY

Thực hiện Nâng cấp Domain Controller bằng phương pháp **Side-by-Side Migration** đảm bảo **Zero Downtime**. Kiểm thử tương thích ứng dụng toàn diện trước khi giáng cấp (Demote) các DC cũ.

### HOW

#### 4.1 Quy trình Side-by-Side Migration (Từng bước chi tiết)

```
[DC01/DC02 - Win Server 2012 R2]                  [DC03/DC04 - Win Server 2022 Mới]
               │                                                 │
               ├────── 1. Adprep /forestprep & domainprep ──────>│
               ├────── 2. Join Domain & Promote DC2022 ─────────>│
               ├────── 3. Replicate Active Directory & SYSVOL ──>│
               ├────── 4. Transfer 5 FSMO Roles via PowerShell ─>│
               │                                                 │
      [ GIAI ĐOẠN THỦ NGHIỆM & QUAN SÁT: 14 - 30 NGÀY ]          │
               │                                                 │
               ├────── 5. Application & Legacy Validation ──────>│
               ├────── 6. Demote DC01/DC02 Cũ ──────────────────>│
               └────── 7. Clean up Metadata & Raise Level ──────>│
```

##### Step 1: Mở rộng Active Directory Schema

Trên DC đang nắm giữ FSMO Schema Master, mount file ISO Windows Server 2022 và chạy:

DOS

```
d:\support\adprep\adprep.exe /forestprep
d:\support\adprep\adprep.exe /domainprep
```

##### Step 2: Promote Server 2022 Mới (DC03)

Cài đặt Role AD DS & DNS Server trên DC03. Promote thành Additional Domain Controller trong Domain `qve.local`.

##### Step 3: Chuyển giao 5 Vai trò FSMO Roles

Chạy lệnh PowerShell trên DC03:

PowerShell

```
Move-ADDirectoryServerOperationMasterRole -Identity "DC03-2022" -OperationMasterRole SchemaMaster, DomainNamingMaster, PDCEmulator, RIDMaster, InfrastructureMaster -Force
```

#### 4.2 Checklist Kiểm thử Tương thích Ứng dụng Bắt buộc (Application Validation Suite)

### 4. QUY TRÌNH ROLLBACK PLAN CHI TIẾT CHO TỪNG HẠNG MỤC CHANGE (ITEMIZED ROLLBACK PLANS)

Không dùng kế hoạch Rollback chung chung. Mọi Yêu cầu Thay đổi (Change Request - CR) phải đính kèm quy trình Rollback riêng biệt theo mẫu dưới đây:

#### Ví dụ A: Rollback Plan cho Hạng mục "Tắt SMBv1"

```
[PRE-CHECK]      : Chạy Wireshark / Network Capture kiểm tra còn SMBv1 Traffic không.
[IMPLEMENTATION] : Áp dụng GPO Disable SMBv1 cho nhóm Server/Workstations Tier A.
[VALIDATION]     : Kiểm tra kết nối File Share từ các máy Client Tier A.
[TRIGGER ERROR]  : Nếu phát hiện máy in/scan hoặc phần mềm nghiệp vụ bị mất kết nối > 15 phút.
[ROLLBACK STEPS] : 
  1. Unlink GPO Disable SMBv1 khỏi OU bị ảnh hưởng.
  2. Thực thi lệnh trên Client/Server lỗi qua PowerShell:
     Set-SmbServerConfiguration -EnableSMB1Protocol $true -Force
  3. Restart dịch vụ Server service hoặc Reboot máy.
  4. Kiểm tra lại kết nối ứng dụng.
```

#### Ví dụ B: Rollback Plan cho Hạng mục "Chuyển giao FSMO Roles sang DC2022"

```
[PRE-CHECK]      : Kiểm tra netdom query fsmo xác nhận DC cũ nắm giữ roles.
[IMPLEMENTATION] : Chạy Move-ADDirectoryServerOperationMasterRole trên DC2022.
[TRIGGER ERROR]  : DC2022 bị sập hoặc mất kết nối mạng ngay trong quá trình transfer.
[ROLLBACK STEPS] :
  1. Ngắt kết nối Network (Disconnect vNIC) của DC2022 trên vSphere.
  2. Trên DC cũ (Win 2012 R2), dùng lệnh Seize Role để cưỡng chế lấy lại FSMO Roles:
     Move-ADDirectoryServerOperationMasterRole -Identity "DC01-2012" -OperationMasterRole SchemaMaster, DomainNamingMaster, PDCEmulator, RIDMaster, InfrastructureMaster -Force -Seize
  3. Xóa Metadata của DC2022 lỗi bằng ntdsutil.
  4. Khôi phục hoạt động của AD trên DC01 cũ.
```
